## 背景与目标（本轮需求总述）

在个人任务管理应用（Vite + React + TS + Zustand + persist）上迭代一版 **对齐飞书任务「进度 + 动态」思路** 的能力，同时落实以下产品约束：

1. **创建**：用户只能通过既有 **FAB「新建任务」** 增加任务；**不得**通过「点击任务卡片」进入任务属性（标题、描述、分类、优先级、实施周期）的编辑界面。
2. **日期**：不再使用单日「计划日期」；改为 **实施日期 / 实施周期**：**开始日期 + 结束日期**（均为 `YYYY-MM-DD`）。
3. **进度**：在 **独立的「进度与日报」界面** 中维护 **完成百分比** 与 **按日填写的进展记录**（可带每次提交时的进度快照），并持久化。
4. **完整性**：其余交互与字段参考 **飞书任务** 的常见能力，在个人版、纯前端前提下落到 **一期必做清单**；明确定义 **一期不做** 的项，避免范围漂移。

## 一、交互与入口（与用户约束对齐）

### 1.1 新建任务（唯一入口）

- 仅通过主界面右下角 **FAB + 模态表单** 创建任务。
- 提交后调用 Zustand `addTask`（或等价 action），由 **persist** 写入 `localStorage`（**key 前缀**保持 `taskApp_`，与 AGENTS 一致）。

### 1.2 禁止「点卡片 = 改任务属性」

- **任务卡片主体**（标题区、描述摘要、分类/优先级/日期展示等区域）**不得**绑定 `onClick` 或等价行为以打开「任务属性编辑」弹窗或路由。
- **允许**在卡片上放置 **独立、可聚焦的控件**（例如右侧「⋯」菜单、或明确的「更新进度」文字按钮 / 图标按钮），仅用于打开 **「进度与日报」侧栏/弹层**；该类控件须具备独立 `aria-label`，且 **不得**承担「编辑标题、实施周期、优先级」等属性编辑职责。
- **若一期不提供属性二次编辑**（标题/周期等仅创建时可填）：须在界面文案中说明「仅支持新建时填写基本信息；后续仅可更新进度与状态」，并在验收中验证无属性编辑入口。

### 1.3 进度与日报（独立界面）

- **完成百分比**、**每日进展**、**任务状态** 的修改 **仅** 在 **「进度与日报」** 界面完成（侧栏或全屏模态均可，二选一需在实现说明中固定）。
- 关闭侧栏后，列表中卡片可 **只读展示** 进度条、百分比、状态、**最新一条进展摘要**；展示区仍遵守 1.2，**不可点进属性编辑**。

## 二、数据模型（建议形态，实现时可等价命名）

在现有任务模型上演进（与 store / persist 兼容），**至少**包含：


| 概念   | 字段（示例名）                                    | 说明                               |
| ---- | ------------------------------------------ | -------------------------------- |
| 实施周期 | `implementationStart`, `implementationEnd` | `YYYY-MM-DD`，均必填；**End ≥ Start** |
| 完成度  | `progressPercent`                          | 整数 **0–100**                     |
| 状态   | `status`                                   | 枚举见下文                            |
| 每日进展 | `progressLog`                              | **有序数组**；元素见下文                   |


`**progressLog` 单条元素（最小集）：**

- `id`：字符串（可用 `crypto.randomUUID()`）
- `date`：`YYYY-MM-DD`（用户可改，默认当天本地日期）
- `note`： string，**必填**（trim 后非空）
- `progressSnapshot`： number 0–100，**可选**（保存提交瞬间的 `progressPercent`，方便时间轴回看）

`**status` 枚举（一期建议与飞书粒度接近）：**

- `not_started`：未开始  
- `in_progress`：进行中  
- `blocked`：阻塞  
- `completed`：已完成  
- `cancelled`：已取消

**与进度、状态的联动规则（一期固定）：**

- 用户将状态设为 `**completed`** 时，**自动**将 `progressPercent` 置为 **100**（若当前不足 100）。
- 状态为 `**completed` / `cancelled`** 时：**禁止**再新增进展日志（或按钮禁用并提示）；已存在日志只读展示（实现二选一，须在 PR 说明中写死）。

**历史数据迁移：**

- 若 store 中仍存在旧字段 `scheduledDate`：加载时 **一次性迁移** 为 `implementationStart = implementationEnd = scheduledDate`，并删除或忽略旧字段（以不破坏 persist 为前提，在代码中做 versioned migrate）。

## 三、时间视图与筛选规则（必须写清、测到）

沿用 **月 → 周 → 日** 导航与 `referenceDate`（或等价锚点）的前提下，**列表是否展示某任务**采用统一规则：

- 记任务实施区间为 [start, end]（含端点的日历日），记当前视图的「锚定日历日」为 D（即与日/周/月筛选逻辑一致的参考日，见现有 `todayISODate` / store 行为）。
- **展示条件**：**实施区间与「以 D 所代表的日/周/月」在日历上有交集**即显示。  
  - **日视图**：D \in [start, end]  
  - **周视图**：该周（与现有 `dateInSameWeek` 周定义一致）与 [start,end] 有交集  
  - **月视图**：该月与 [start,end] 有交集
- 必须在 **Vitest** 中为上述交集规则补充用例（可与现有 `dateFilter` 工具一起测，或抽成 `taskVisibility` 工具）。

## 四、参考飞书：一期必做 vs 暂不做

### 一期必做（本轮 prompt「完整」的默认范围）

- 完成百分比 + 可视化进度条（列表或卡片只读摘要亦可）
- 每日进展（带日期、备注、可选进度快照）+ 时间轴/列表展示
- 任务状态枚举及与进度的联动（见上文）
- 实施起止日期 + 校验 + 时间视图筛选
- 新建仅 FAB；禁止卡片主体打开属性编辑；进度仅独立界面

### 一期明确不做（避免对标飞书时无限膨胀）

- **多人协作**、**评论 @**、**附件上传**、**与飞书/其他服务打通**
- **子任务 / checklist**（可记入 AGENTS 或二期 backlog）
- **服务端日历提醒**；仅可做 **本地 UI 提示**（例如结束日前 N 天在卡片角标显示「临期」，可选，若工期不够可删）

## 五、表单与校验（摘要）

**新建任务表单：**

- 标题：必填，trim 非空  
- 描述、分类：选填（沿用现有交互或使用「预设 + 自定义」）  
- 优先级：必选，默认「中」  
- **实施开始 / 实施结束**：必选，`YYYY-MM-DD`，且 **结束 ≥ 开始**  
- 新建时：`progressPercent` 默认 **0**，`status` 默认 `**not_started`**，`progressLog` 默认 **[]**

**进度界面表单：**

- 可更新 `progressPercent`（0–100）、`status`  
- 可追加一条 `progressLog`：`date`、`note` 必填；`progressSnapshot` 默认写入当前 `progressPercent`（若实现简单可自动带）
